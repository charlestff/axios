# Experiment Results

Generated by `python -m poker_sim.experiments` (3 agents: an equity-driven
`Pro`, a tight human-like agent, a loose calling-station). Raw numbers in
`poker_sim_results.json`. Runtime ≈ 20 min on one core.

## Q1 — Does the strategy win?

### Texas Hold'em (2 cards), 1000 hands

| Agent | profile | bb/100 |
|-------|---------|-------:|
| Pro   | strategy | **+6.45** |
| Tight | human   | +4.30 |
| Loose | human   | −10.75 |

The disciplined equity strategy is the most profitable; the loose
calling-station is the clear loser. Directionally exactly what poker theory
predicts. (1000 hands is still high-variance — treat the magnitude as
indicative, the sign as meaningful.)

### Five Card Draw (5 cards), 1000 hands

| Agent | profile | bb/100 |
|-------|---------|-------:|
| Pro   | strategy | **−184.25** |
| Tight | human   | +267.30 |
| Loose | human   | −83.05 |

**The "pro" agent loses badly here — and that is an honest, useful finding, not
a glitch.** Our `draw_equity` model evaluates a holding against *random static*
5-card opponent hands; it does **not** model that opponents will draw and
improve. So it systematically **overvalues** marginal made hands, and the
aggressive agent commits chips while behind. The tight agent's higher thresholds
sidestep the miscalibration and it profits.

Lesson for the study: **automation is not automatically winning.** A bot whose
evaluation model is miscalibrated to the game variant is *unprofitable*. Fixing
this means modelling opponent draws in `equity.py` (left as future work, and
clearly flagged as a limitation).

## Q2 — Can a static detector catch the bot?

### Static detector vs the default (regular-timing) bot

| metric | value |
|--------|------:|
| accuracy | 0.978 |
| bot recall | **1.000** |
| precision | 0.936 |
| human false-positive rate | 0.032 |

A naive automated agent with consistent timing is caught **every time**, at a
~3% false-positive cost against humans. Cheap and effective.

### Jitter sweep — the cat-and-mouse curve

The bot adds increasing timing noise (`jitter`) to look human:

| jitter | bot recall | human FPR | accuracy |
|-------:|-----------:|----------:|---------:|
| 0.00 | 1.000 | 0.034 | 0.977 |
| 0.10 | 1.000 | 0.037 | 0.975 |
| 0.20 | 1.000 | 0.036 | 0.975 |
| 0.30 | 0.989 | 0.037 | 0.972 |
| 0.50 | 0.722 | 0.044 | 0.881 |
| 0.80 | **0.076** | 0.052 | 0.666 |

**This is the core result.** A static timing-based detector is robust to small
jitter but collapses once the bot's timing variance approaches human levels:
recall falls from 100% to ~8%. And the adaptive detector that tightens its
threshold to compensate pays for it in a rising human false-positive rate
(0.034 → 0.052) — the unavoidable tension of any anti-automation system.

## Takeaways for the InfoSec write-up

1. A behavioural (timing-regularity) detector **cheaply defeats naive
   automation** but is **not** a durable defence against an adversary willing to
   randomise behaviour — recall degrades sharply, and tightening the detector
   shifts cost onto false positives against real users.
2. Therefore robust anti-automation cannot rely on a single static behavioural
   signal; it needs server-side, multi-signal, and continuously-updated
   approaches.
3. Winning at the game still requires a *correctly calibrated* model — the draw
   result shows a miscalibrated agent loses money regardless of automation.
